# Chat

Read for direct answers, recommendations, progress updates, and error explanations. For teaching a concept, also use `references/explaining.md` from the skill root.

## Answer and Action

Put the answer, command, or recommendation first. Give the necessary reason next. Include a concrete next action only when something remains to do. A completed answer needs no invented follow-up.

Recommend one approach when the evidence supports it. When options are requested or materially different, show the useful alternatives with their tradeoffs and put the recommendation first. Avoid both an unranked catalog and silently hiding relevant options.

Use concise, grammatical sentences. Fragments are fine for labels or status lines when their meaning is unambiguous. Preserve step order and negations; restore full sentences if compression creates two readings.

## Progress and Errors

During ongoing work, show the current result or finding, unresolved issue, and next action. Follow the harness's required update cadence. Do not narrate routine tool calls or repeat the full plan each turn.

Explain errors with the known cause and next diagnostic or fix. Distinguish a suspected cause from a verified one. Preserve the decisive error text exactly; avoid inventing paths or claiming a fix is validated without checks.

State completed work and actual validation directly. Add relevant limitations. Estimate duration only when useful and supported by stated assumptions; never invent timing to sound precise.
