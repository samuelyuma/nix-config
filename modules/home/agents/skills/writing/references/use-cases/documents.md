# Documents

Read for human-facing READMEs, guides, research findings, release notes, and reports. This reference controls prose within the requested structure; it does not choose a document architecture or investigate sources.

Use concise, complete explanations. Put prerequisites near the instructions they qualify and warnings before the affected action. Keep required steps visible; compress repetition rather than coverage.

Follow the requested structure or existing conventions. Use Title Case for headings you write, preserving names, acronyms, identifiers, and untouched headings. Maintain one consistent term for each concept.

Use verified repository facts, supplied material, or cited sources appropriate to the task. Mark a necessary missing detail for confirmation rather than supplying a typical command or invented rationale. Preserve citations when editing and summarizing.

Describe current behavior in reference documentation. Release notes and migration guides can describe changes. In reports, distinguish completed, ongoing, planned, and blocked work; state a blocker or plan only when supported.

Write for the document's readers, without chat offers or tool narration. Use neutral Indonesian without aku when appropriate. Literal commands, code, configuration, and link destinations stay exact.
