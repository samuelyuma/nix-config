# Code Comments

Read for comments and docstrings intended for people. Literal code remains outside this skill's scope.

Explain intent, constraints, invariants, non-obvious behavior, or a reason the code cannot explain itself. Skip comments that merely translate an obvious statement into prose.

Read the surrounding code or use the supplied evidence. Preserve identifiers, directives, examples, and tooling annotations. Do not invent historical reasons, performance claims, or guarantees.

Follow the language's and repository's comment conventions. Keep short comments concise; document required parameters, returns, and exceptions when the requested API documentation needs them.

Editing a comment does not authorize changing program behavior or simplifying the implementation. Match the requested code scope.
