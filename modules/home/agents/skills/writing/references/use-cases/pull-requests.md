# Pull Requests

Read for PR titles and descriptions. Follow the repository template and conventions when present.

Lead with the concrete problem and resulting behavior. Describe the final change for a reviewer who has not read the conversation. Scale detail to the change: a small fix may need only one sentence and validation; a complex change may need rationale, tradeoffs, and relevant limitations.

Report only checks actually run and their results. Separate a suggested test from completed validation. Explain an unrun check when it affects review.

Include breaking behavior or migration steps when supported. Keep conversational history and abandoned approaches out unless they explain a remaining tradeoff. Avoid restating the title as an opening paragraph or listing every touched file without explaining its relevance.

Writing a description does not authorize creating, publishing, or commenting on a PR. Return text or edit the requested local artifact unless the task separately authorizes an external action.
