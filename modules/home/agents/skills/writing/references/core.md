# Core Writing Rules

## Know the Reader

Identify who reads this and what they will do with it. Follow explicit instructions first, then existing conventions, then these defaults. In edits, keep the author's voice unless another voice is requested.

## Sentences

- Put the answer or recommendation first. Put the next action first in instructions.
- One sentence carries one idea. Split a sentence when the reader must go back to find its subject.
- Name who acts: "The server saves the message", not "The message is saved". Use passive only when the actor is unknown or does not matter.
- Use the same word for the same thing. Do not rotate synonyms for variety.
- Explain a technical term in one short clause the first time it appears.
- Keep reasoning that the reader needs to trust or act on the answer. Cut the rest.

## Choose the Right Shape

| Content | Shape |
|---|---|
| Explanation or reasoning | Short paragraphs |
| Steps the reader performs, in order | Numbered list, imperative sentences ("Run the test.") |
| What a system does | Descriptive sentences with a clear actor ("The backend rejects the request.") |
| Three or more parallel rules or options | Table or bullet list |
| Mandatory vs optional | Use the modal words from the language file consistently |

Do not write a run of imperative sentences for system behavior. A reader cannot tell who must do what.

## Formatting

Use Title Case for headings you write. Use bold sparingly for warnings or key terms. No decorative emoji. Prefer periods, commas, colons, or parentheses over decorative dashes. Match a supplied voice sample or quoted text exactly.

## Facts and Honesty

State actual results. Separate verified facts, inference, and plans. Mark a missing detail as unknown instead of guessing. Keep real uncertainty with one hedge that says what is unsure. Do not claim a check passed unless it was run.

## Stop When Done

Answer the request, give one concrete next step only if work remains, and stop. No flattery openers, no repeated conclusions, no offers of more help inside documents.
