# Root README

The `README.md` at the repository root. Audience: a developer who has just opened the repo.

## Skeleton

Include a section only if there is grounded content for it.

1. **Title and One-Line Description.** What the project is, taken from the manifest description or existing docs.
2. **Badges** (optional). Only for status backed by a real file, such as a CI workflow.
3. **Overview.** Two to four sentences on what it does. Only what the code and config show. Do not invent goals or marketing claims.
4. **Quick Start.** Prerequisites, install, run. Commands must work when run in order and must come from manifests, task runners, or config. Use the package manager the repo actually uses (check the lockfile).
5. **Usage.** The most common ways to use it, with real commands or endpoints.
6. **Configuration.** A table of environment variables from `.env.example` or config files: name, purpose, default, required. Names only, never real values.
7. **Project Structure.** A short tree of top-level directories, only when the layout is not obvious. One line of purpose each.
8. **Development.** Test, lint, format, and build commands.
9. **Deployment.** One or two sentences and a link to the workflow README if one exists. Do not duplicate it here.
10. **Contributing and License.** Only if `CONTRIBUTING.md` or a license file exists. Link to them.

## Notes

- Architecture diagram: only when the code shows 3 or more components that interact. Draw it from what was read.
- Keep the first screen useful: title, description, quick start before anything else.
- For an existing README, follow the surgical-update rules in `SKILL.md`. Keep its section order and voice.
