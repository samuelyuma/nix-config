# Root README

Help a new reader understand the project and complete the first useful action. Read the project entry points, manifests, task definitions, safe configuration schemas, and existing onboarding documentation.

## Flexible Skeleton

1. **Name and Purpose.** Explain what the project does and for whom. Keep claims within the implementation or supplied brief.
2. **Quick Start.** Put prerequisites before verified installation and run steps. Use the actual package manager, lockfile, and task runner. Distinguish local development from production setup.
3. **Usage.** Show the main supported action with a grounded example.
4. **Configuration.** Explain relevant setting names, purposes, defaults, and requirements from safe schemas or supplied documentation. Never show real credentials.
5. **Development.** Include supported checks and links to contribution guidance.
6. **Structure or Architecture.** Add only when readers need help navigating or understanding relationships. Link deeper feature and workflow guides instead of duplicating them.
7. **License and Related Material.** Link existing files; make a missing license a question rather than choosing one.

Keep the first screen useful. Preserve established section order in focused updates. Badges need a verifiable source. A directory tree is useful only when the layout needs explanation.
