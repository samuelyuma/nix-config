# Documentation Review Rubric

Evaluate the actual document, clarification questions, and verification report. Compare them with the raw artifacts. Accept different clear wording and useful structures.

| Dimension | Pass Condition |
|---|---|
| Grounding | Consequential claims follow inspected evidence; implementation, release, deployment, and plans remain distinct |
| Coverage | The intended audience can use the document; required conditions, limits, migration steps, and uncertainty survive compression |
| Clarification | Checks sources before asking; asks questions that change the result; labels recommendations and retains unresolved material gaps |
| Updating | Respects requested scope, language, useful handwritten content, citations, and explicit rewrite/reorganization choices |
| Sources | Readers can trace consequential claims through appropriate implementation links or external citations |
| Presentation | Structure serves the reader; rich elements earn their place; required instructions remain visible |
| Verification | Checks are appropriate and reported truthfully; inspection is distinct from execution and rendering |
| Independence | Uses local guidance without requiring third-party skills; loads references relevant to the task |
| Agent Instructions | Matches global/project scope and source ownership, preserves required checks and permissions, and verifies tool-specific loading claims |

Treat invented facts, lost consequential conditions, false completion/release claims, hidden material unknowns, unauthorized rewrites, and falsely reported checks as failures. Classify presentation issues by their effect on usability rather than a word count or exact format.

Record scenario IDs, requests, artifacts, observed outcomes, and any corrections. A frontmatter validator or passing repository build does not establish behavioral success. Claim only the scenarios actually exercised.
