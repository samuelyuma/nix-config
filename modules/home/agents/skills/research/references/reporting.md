# Research Files and Reports

Create a file only when requested. Follow the requested destination, otherwise an established convention; clarify placement when it materially affects the result. Updating research notes does not authorize rewriting unrelated documentation.

For a full report, use the user's `documentation` skill and its research-report reference when available. That skill organizes the investigated findings; it does not replace the investigation. Optional local skill paths are `../../documentation/SKILL.md` and `../../documentation/references/research-reports.md`, relative to this reference. Use the fallback below when unavailable.

## Standalone Fallback

Use a flexible structure suited to the reader:

1. **Question and Answer.** State the supported conclusion, including consequential uncertainty.
2. **Scope and Evidence.** Identify relevant environment, versions, dates, inspected sources, and access limits.
3. **Findings.** Present decision-relevant claims with citations near them. Separate observations from inference.
4. **Recommendation or Tradeoffs.** Include only when the question calls for a decision; label proposals and judgment.
5. **Open Questions.** Keep material unresolved gaps visible and identify what could settle them.

Omit irrelevant sections. Label a report Draft when unresolved facts or decisions prevent its intended use; a report documenting inconclusive findings can still be complete about those findings. Preserve citation targets, measurements, conditions, and exact technical literals.

For updates, retain useful handwritten content, language, and structure unless translation, reorganization, or rewriting was requested. New files use explicit language, then surrounding document conventions, then the current user message. Chat follows the user's current language.

Before delivery, check consequential claims against their sources, resolve local citation paths and relevant anchors, and review any comparisons for equivalent conditions. Report source inspection separately from executed checks. Deliver the requested artifact and identify remaining limits without implying implementation or publication.
