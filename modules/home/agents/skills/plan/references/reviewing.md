# Review and Update Existing Plans

Read when the user supplies a plan for critique or revision. Check it against current repository evidence and the latest agreed requirements; the plan itself is not proof of current behavior.

## Review

Trace consequential steps to actual implementation, configuration, tests, or supplied evidence. Identify stale paths, unsupported assumptions, missing prerequisites, unnecessary scope, unresolved choices, and acceptance criteria that could pass while the requested behavior still fails.

Prioritize findings by their effect on correctness or execution. Explain each material problem with evidence and a useful correction. Preserve valid decisions and useful handwritten content. A review request can end with findings; rewriting or implementation requires the corresponding request.

## Update

Change the affected steps and their dependents while keeping unrelated valid content. Reorder work when dependencies change. If prior decisions conflict with new evidence, explain the conflict and recommend a resolution; ask about consequential choices rather than silently replacing them.

Preserve truthful progress: a checkbox or an old success claim does not establish completion. Verify reported completion where possible, otherwise label it as reported or unverified. Keep completed work, remaining work, and superseded proposals distinguishable without imposing a status system on a small plan.

Deliver the revised plan and summarize meaningful changes and remaining gaps. Do not erase uncertainty merely to make the plan look ready.
