# Plan Review Rubric

Evaluate the actual plan, questions, inspected evidence, and tool actions together.

| Dimension | Pass Condition |
|---|---|
| Scope | Covers the requested outcome and mode without unrelated work, unrequested files, or implementation |
| Grounding | Uses current repository evidence, verifies existing paths and commands, and labels new files or proposed checks |
| Decisions | Asks only consequential missing choices, carries answers forward, and preserves useful agreed decisions |
| Steps | Intended changes, affected areas, dependencies, and completion checks are concrete enough to execute |
| Diagnosis | Distinguishes symptoms, hypotheses, source-supported causes, observed reproduction, and missing evidence |
| Verification | Acceptance criteria cover behavior; actual check outcomes are separate from future verification |
| Revision | Reviews or updates only as requested, identifies stale assumptions, and preserves valid content and truthful status |
| Handoff | Identifies ready, investigative, or blocked work and respects existing execution authorization |
| Decisions in One Place | Open decisions are collected near the top with recommendations and linked to the steps they block |
| Proportion | Detail and investigation fit the task; no mandatory third-party skills, agents, fixed step counts, or templates |

Fail fabricated paths, commands, evidence, run results, or confirmed causes; hidden consequential blockers; unsupported fixes; loss of agreed constraints; and unauthorized implementation. A passing static validator or Nix build proves packaging, not plan quality.

Record the realistic request, raw inputs, generated outcome, checks actually run, and scenarios exercised. Accept different clear wording and useful structures.
